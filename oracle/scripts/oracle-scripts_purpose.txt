Purpose notes for oracle/scripts/ -- why each piece exists and, where it
matters more, what was deliberately left out.  Everything here was
learned during the first end-to-end run on 2026-08-08, which took a Guix
image from `guix system image` to a RUNNING instance at a public IP.

========================================================================
Why these are Guile scripts
========================================================================
Repo policy (CLAUDE.md): Guile for anything that runs on a Guix system.
These run on the operator's local Guix machine.  A practical consequence
drove one design rule: core Guile has NO JSON parser (guile-json is a
separate package), so every oci CLI call uses --query/--raw-output and
the CLI does all JSON work.  Do not "improve" this by parsing JSON in
Guile unless you also add guix-shell plumbing for guile-json.

The scripts load oci-common.scm with (load ...) relative to
(car (command-line)) instead of use-modules, so they work from any
checkout path with zero GUILE_LOAD_PATH setup.

========================================================================
oci-common.scm
========================================================================
prompt-tty          reads /dev/tty, never stdin -- repo-wide pattern;
                    stdin may be a pipe from the caller.
oci / oci/status    every call sets SUPPRESS_LABEL_WARNING=True; without
                    it the CLI prints key-security advice on EVERY
                    invocation and that noise lands inside --raw-output
                    capture paths.
poll-until          all long waits go through one helper so every
                    script's waiting behavior (dots, timeout, message)
                    is identical.

validation event helpers
                    encode monotonically sequenced JSONL without guile-json,
                    reject malformed events and gaps, and permit an overlapping
                    prefix after reconnect.  A gap is never silently skipped:
                    resilient telemetry is evidence only if it can say exactly
                    which events it inspected.

Statement of omission: validation-common.scm does not reconnect to a guest or
consult OCI.  It is the pure layer used to prove replay behavior offline; the
controller owns transport, lifecycle polling, and console capture.

Disposable ownership gate
                    Stage 0 and Stage 1 record manager, artifact state,
                    resource type, exact OCID, and allowed operations locally.
                    Immediately before termination they perform one fresh OCI
                    read of the exact instance's OCID and three ownership tags.
                    Missing tags serialize as `null`; absent, malformed, stale,
                    mismatched, or handed-off facts all block termination.

Statement of omission: a display name, expiry time, successful command, or
locally recorded OCID alone never authorizes mutation.  Those facts are useful
for diagnosis, not proof that the cloud resource is still controller-owned.

validation-lifecycle.scm
                    provides exact-run status, guarded cleanup, and fail-safe
                    handoff. Handoff writes the local marker and HANDED_OFF
                    state before changing OCI, then requires a fresh OCI
                    confirmation of exact OCID, run ID, and state. An
                    interruption therefore protects rather than exposes data.

Statement of omission: there is no name-based destroy, bulk cleanup, adoption,
or HANDED_OFF-to-IN_TEST transition. Each would widen deletion authority and
requires a separate explicit design and user instruction.

========================================================================
oci-inspect.scm
========================================================================
Stable read-only operations interface
    `auth`, `inventory`, `instance`, and `evidence` replace improvised OCI
    command strings during diagnostics.  This is useful both to a human
    operator and to an LLM resuming from the restart checkpoint.

No lifecycle mutation
    The script deliberately contains no launch, stop, or terminate command.
    Mutation remains in the purpose-specific controllers, where resource
    ownership and cleanup policy are explicit.

Evidence keyed by exact OCID
    Instance diagnostics require an `ocid1.instance.*` argument and write
    instance, VNIC, and serial-console evidence beneath a caller-selected
    local directory.  Display names are never accepted as cleanup identity.

========================================================================
01-setup-client.scm
========================================================================
python via `guix install python`
    Guix packages the Go OCI SDK but not the CLI.  The CLI is Python.
    A venv under ~/.venvs/oci-cli keeps pip packages out of the Guix
    profile; the symlink into ~/.local/bin makes `oci` a normal command.

Console-GENERATED API key, not locally-generated
    First attempt had the user paste a locally generated public key into
    the console form; transcription of a 7-line PEM through a chat/copy
    path corrupted it silently (a mangled key still LOOKS like a key).
    "Generate API key pair" + "Download private key" is two clicks and
    cannot be mistyped.  The script then finds the newest ~/Downloads/
    *.pem, asks for confirmation, and moves it into ~/.oci with 600.

Fingerprint computed locally
    MD5 over the DER SubjectPublicKeyInfo, colon-separated -- computed
    with the venv's own `cryptography` lib because openssl(1) is not
    on a stock Guix system.  Printing it lets the user compare against
    the console's displayed fingerprint, which is the fastest way to
    detect "downloaded one key, Added a different one".

Auth poll after setup
    A fresh key returns NotAuthenticated for up to ~a minute.  Without
    the poll, users conclude the setup failed and start over.

Statement of omission: `oci session authenticate` (browser flow) was
tried and rejected as the primary path -- it needs a running local
callback listener, the token expires hourly, and it cannot be resumed
by a script the next morning.  API keys are durable.

Statement of omission: no attempt to read tenancy/user OCIDs from a
previous machine's ~/.oci.  Recovering config from an old disk needs
root to mount it; simpler to re-enter two OCIDs.

========================================================================
02-build-image.scm
========================================================================
pty via script(1)
    `guix system image` output redirected to a file dies before the
    build starts: "terminal-window-size: Inappropriate ioctl for
    device".  script(1) provides a pty and tees to the log.

setsid detachment
    The first two "failed" builds of this image were healthy builds
    whose controlling session died.  Detached + logged means the build
    survives the terminal, and reruns find the finished path in the log.
    Guix's derivation cache makes interrupted builds resume, so kill
    and rerun is always safe.

authorized-key.pub prompt
    The key is baked into the image and is the only way in; the build
    fails at evaluation without it (local-file).  The script offers the
    keys in ~/.ssh rather than silently picking one: baking the wrong
    key = unreachable instance.

Statement of omission: no --dry-run pre-pass.  It doubles evaluation
time and the real build fails just as clearly at the same point.

========================================================================
03-smoke-test.scm
========================================================================
Serial console over TCP, not a unix socket
    sun_path is limited to 108 bytes; socket paths inside deep per-
    session scratch directories exceed it and QEMU refuses to start.
    TCP on 127.0.0.1 has no such limit and Guile's socket API speaks it
    directly.

Sentinel is computed by the GUEST ($((41+1)) -> 42)
    Matching command completion by echoing a literal sentinel fails
    because the ECHOED COMMAND LINE contains the sentinel too, so the
    matcher fires before the command runs.  The guest computing it
    means the literal string never appears in the input line.

Commands must not end in `&`
    console-run appends " ; echo SENTINEL-..." and `& ;` is a bash
    syntax error.  Background with "... & true".

Root console login with no password
    The image sets no root password, so the serial console gives a root
    shell.  That is what makes unattended key injection possible.  (On
    the real OCI serial console this is also the recovery path; whether
    to lock root's console later is a hardening decision for the user.)

Throwaway key, not the user's key
    The single most misleading failure of the first run: `ssh -o
    BatchMode=yes` with a passphrase-protected key prints "Permission
    denied (publickey)" -- while the server-side `sshd -ddd` shows
    "Accepted key ... Postponed publickey" and the CLIENT hanging up
    because BatchMode cannot prompt for the passphrase to sign.  It
    looks exactly like README failure mode #2 (wrong key baked in) but
    is purely client-side.  A fresh passphrase-less key exercises the
    same server path with no ambiguity.

Key injected into the scratch COPY only
    The store image stays byte-identical to what 04 uploads; the tested
    artifact and the deployed artifact differ only by the injected line
    in a copy that is deleted afterwards.

What a PASS certifies: serial console (= OCI console) login prompt,
root-by-label mount, sshd accepting authorized_keys, completed login
for the locked-password account (guix:!: + UsePAM yes -- the purpose
file of the image asserts this works; this test is the proof), and
passwordless sudo.

========================================================================
04-deploy.scm
========================================================================
Idempotency by display-name lookup
    Cloud steps fail halfway (quota, network, typo).  Every ensure-*
    looks up before creating, so rerunning after ANY failure continues.
    The trade-off, stated: a rebuilt qcow2 does not re-import while an
    AVAILABLE image named guix-oracle exists -- delete that image in
    the console (or rename %image-name) to force it.  The script says
    this aloud when it skips the upload.

PARAVIRTUALIZED launch mode
    Must match the BIOS/MBR layout of the qcow2 image type.  NATIVE
    boots UEFI and would need qcow2-gpt + grub-efi-bootloader.

Networking created in code, not by the console wizard
    VCN 10.0.0.0/16, internet gateway, 0.0.0.0/0 route in the DEFAULT
    route table, subnet 10.0.0.0/24.  The default security list already
    allows SSH from 0.0.0.0/0, so no security-list edits are needed for
    port 22.  Web serving later needs 80/443 added there.

No cloud-init metadata
    --metadata ssh_authorized_keys only works for images running
    cloud-init.  Guix has none; the key is baked in.  Passing metadata
    anyway would silently do nothing and mislead readers.

Availability-domain walk on "Out of host capacity"
    The launch used to take data[0] -- the first AD the CLI listed --
    and stop there.  Always Free VM.Standard.E2.1.Micro capacity is
    routinely exhausted in popular regions, and Oracle answers a full
    AD with `Out of host capacity.' (service code OutOfCapacity, HTTP
    500).  That landed on the user as a raw oci CLI traceback at the
    very last step, after an upload and a 5-20 minute image import had
    already succeeded.  The script now enumerates the ADs and tries each
    once, in list order, saying which one it is on.

    Capacity in one AD says nothing about the next -- they are separate
    physical pools -- which is exactly why the walk is worth doing and
    why a repeat of the SAME AD is not.

launch-error-kind: four kinds, only one of which walks
    capacity -> try the next AD.  limit (LimitExceeded / quota) -> stop,
    because every AD draws on the same tenancy limit and the walk would
    collect the identical refusal N times.  other (bad subnet OCID,
    unusable image, malformed parameter) -> stop and print the CLI's own
    words.  none -> no error signature.

    Matching is on the message text, case-insensitively, not on the HTTP
    status: OutOfCapacity arrives as a 500, which is indistinguishable
    from a transient server fault by status code alone.

    The procedure is pure and takes a string, so
    oracle/tests/test-oracle-capacity.scm exercises it offline against
    canned CLI output.  That test reads the definitions out of this
    script rather than loading it (loading would run main and call
    Oracle), which is why launch-error-kind and capacity-advice must
    keep depending on core Guile only -- no oci-common helpers inside
    them.  There is deliberately NO test hook in 04-deploy.scm itself.

ADs enumerated by index, not as an array
    --query 'data[N].name' --raw-output, N incrementing until the query
    comes back empty.  Asking for 'data[*].name' returns a JSON LIST,
    which --raw-output does not flatten, and parsing it would need
    guile-json -- the one dependency these scripts exist without (see
    the top of this file).  N+1 small API calls for an N of 1-3.

Statement of omission: NO retry loop, anywhere.  Not per-AD, not
whole-walk, not with backoff.  Every AD is tried at most once and then
the script stops.  Exhausted Always Free capacity is a queue measured
in hours to days, not seconds; a retry loop cannot make a host appear,
it just turns one user's disappointment into API traffic that can get
the tenancy rate-limited.  "Come back later and rerun" is the honest
answer, and the script's own idempotency is what makes it a cheap one:
a rerun skips straight past the bucket, the image and the network to
the launch.

Statement of omission: VM.Standard.A1.Flex (Ampere ARM) is ADVICE TEXT
ONLY, never a fallback the script takes.  It is tempting -- it is the
other Always Free shape and its capacity pool is usually free when
E2.1.Micro's is not -- but the qcow2 this repo builds is x86_64 and
will not boot on ARM.  Silently retrying on A1.Flex would produce a
successful launch, a RUNNING instance, and an instance that never
reaches the SSH banner, with the failure hidden inside a boot that no
one is watching.  A1.Flex is also a flexible shape and needs
--shape-config with an OCPU count and memory size, which a fixed shape
does not take.  Real ARM support means building an aarch64 image; that
is separate work, and until it exists the honest thing to print is a
direction, not a flag.

Statement of omission: no automatic region change either.  Always Free
is granted in the tenancy's HOME region, which is fixed at signup, so
"try another region" is really "create another tenancy" -- not
something a deployment script should do on a user's behalf.  The advice
says so plainly rather than implying that editing ~/.oci/config would
be enough.

Exit code on exhausted capacity is 1, not 0
    Nothing was deployed, so the script must not report success to a
    caller.  "Exit cleanly" here means no Python traceback and no raw
    CLI JSON as the last thing on screen -- an [ERROR] line, the list
    of ADs tried, and the advice.

SSH BANNER check, deliberately not a login
    "Permission denied (publickey)" from a BatchMode probe user proves
    sshd is up, the route/security list work, and auth is enforced.  A
    full unattended login would require an unencrypted private key on
    disk, which this repo will not ask for.  The user performs the
    first real login interactively.

Known open question carried in the final output: the boot volume may be
/dev/sda (virtio-scsi) rather than /dev/vda on OCI, in which case
(targets ...) in oracle-image.scm must be fixed BEFORE the first
`guix system reconfigure`.  First boot is unaffected (GRUB was written
at image-build time).

DISPOSABLE VALIDATION (05-verify-metadata-ssh.scm, validation-common.scm,
validate.scm)

The validator is intentionally separate from 04-deploy.scm.  The deploy script
owns stable, idempotently named installation resources; validation instances
are unique, disposable, and always cleaned up by the OCID recorded locally.
Reusing a display name as the cleanup key would risk terminating the wrong
machine after a partial or repeated run.

The Stage 0 probe exists because QEMU cannot prove the OCI metadata service
installs an SSH key early enough for a real login.  It launches with an
ephemeral public key in ssh_authorized_keys metadata, disables legacy IMDS
endpoints, performs a full key-authenticated login, captures serial-console
history, and terminates the instance and boot volume.  Offline construction
tests never count as that live proof.

validate.scm archives the selected working directory rather than using git
archive: an LLM's code is commonly dirty or untracked, and omitting precisely
those changes would validate the wrong source.  The archive excludes .git and
.oracle-validation, preserves symlinks without dereferencing them, and records
a sorted manifest and SHA-256 before upload.  The requested command is sent as
a file, never interpolated through nested local/SSH shell quoting.

Remote stdout and stderr are merged and copied character-by-character to both
the terminal and a flushed local log.  This preserves everything already
received if SSH or the instance disappears.  Reconnect/replay, heartbeats, and
continuous console capture require a sequenced remote journal and deliberately
remain Stage 2 work.

OCI credentials and the ephemeral private SSH key never enter the guest.  The
private key is removed only after termination succeeds; if cleanup fails it is
retained with the recorded instance OCID so the operator can collect evidence
or terminate manually.  A failed validation is terminated by default.
--keep-on-failure is opt-in because an unenforced promise to clean up later is
not a lifecycle policy.
