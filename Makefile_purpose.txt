The root Makefile gives short, discoverable names to repository workflows that
are otherwise easy to mistype or only partly run.

`test` preserves the full-suite entry point. `check` spells out the two
pre-commit gates in their required order; it deliberately does not regenerate
the manifest because that writes a shared generated file and is only needed
when a covered source changed.

`oracle-test` runs the capacity and validator/controller suites, the two Oracle
suites that are genuinely offline and portable. The preferences and image
evaluation suites import Guix modules unavailable on the macOS development
host. `oracle-test-all` adds both and fails clearly when `guix` is absent.
Focused `oracle-test-*` targets make it cheap to rerun only the affected
boundary while editing.

`gips-test` runs the offline GIPS recipe self-test, Scheme API test suite, and
Guix narinfo signing suite. `gips-rust-test` runs the complete Rust workspace
test suite using Cargo. `gips-check` runs both suites, verifying full Scheme
and Rust parity.

`ORACLE_SOURCE` and `ORACLE_COMMAND` are optional `.env` defaults for repeated
one-shot runs. They are deliberately non-secret and remain visible in
`oracle-help`; command-line `SOURCE=` and `COMMAND=` assignments override them.
The command is not validated as harmless because it is user-declared guest
work, so operators must review it before setting `YES=--yes`.

Cloud lifecycle targets remain explicit. There is no display-name-based or
generic destroy shortcut: mutation and cleanup continue through the exact-run
ownership gate in `validation-lifecycle.scm`.
